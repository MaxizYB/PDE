# 面向 Nature 子刊的自主研究规范

版本：1.1。制定与来源核查日期：2026-10-16；执行与上下文管理修订：2026-10-17。

本规范服务于 PDE 与科学机器学习研究，当前优先参照 Nature Communications 和 Nature Machine Intelligence。它规定从选题、调研、理论与机制分析、方法设计、实验迭代到论文写作和准出的完整流程，不预设具体研究问题或模型架构。

**研究目标：发现一个重要且具有可迁移意义的问题，解释现有方法的关键缺口，形成有独立洞见的简洁方法，以可靠实验建立实质优势，最终形成可复现的论文。**

## 1. 执行总则

1. **研究先于优化。** 每轮先判断最重要的未知是什么，再选择能改变认识或方向的实验。
2. **问题价值不随当前方法的方便程度改变。** 方法失败时修改方法、补充机制分析或重新审视问题，不把任务缩成容易但无价值的特例。
3. **快速迭代每个配置只做一次训练。** 固定一个开发 seed，复用已有模型、数据和结果；最终准出前才安排多 seed 和重复验证。
4. **方法设计由机制推出。** 网络、数值模块、损失和流程各自承担清楚的作用；不靠组件堆叠或命名制造创新。
5. **优先复用，保持清爽。** 一个项目只有一份当前方法、一份证据总账和一份决策日志；历史结果保留但不混成当前结果。
6. **边研究边写作。** 从问题确立起持续更新论证和图表，每次研究改变同时进入方法、证据和稿件，不在最后重新拼故事。
7. **正面阐明贡献，证据支撑主张。** 勇敢提出有价值的问题和一般性解释；用实验解决反例，不用防御式措辞或偷换评价目标回避反例。
8. **自主推进与人类责任并存。** 在已有授权内自主执行、分析和提出阶段判断；关键里程碑提供可复核材料，最终科学结论和投稿由研究者审阅确认。[S7]

本规范中的阶段门、运行记录和实验数量安排是本项目的执行规则，不是 Nature 的官方录用公式。

## 2. Nature 风格与研究定位

### 2.1 官方标准与本项目的转化

| 来源 | 核查到的官方要求 | 转化为本项目的研究要求 |
| --- | --- | --- |
| Nature Communications 范围与编辑流程 [S1–S2] | 对领域专家有重要意义的进展；编辑关注新颖性、影响、概念或方法进展及读者兴趣 | 先明确研究改变了什么认识或能力，再证明它不是常规配置改良 |
| Nature Machine Intelligence 编辑流程 [S3] | 推进领域理解、结论可靠、数据分析支持结论、对读者具有广泛相关性 | 中心洞见、机制验证和可迁移意义必须贯穿全文 |
| Nature Communications 应用研究说明 [S4] | 应用工作也可通过性能和效用形成重要进展；需公平比较并兼顾通用指标 | 不强迫发明新 backbone；但要证明真实任务价值、替代方法差距和完整代价 |
| 数据、代码与投稿规范 [S5–S6] | 支撑结论的数据与核心代码可审阅；提供获取说明和图表源数据 | 从研究开始记录来源、配置、源码、权重和原始结果的对应关系 |

这两种目标期刊不是同一种叙事。NMI 更适合突出学习与计算方式的新原则；Nat Commun 可以从科学计算需求和物理后果展开。同一工作选择不同叙事时，实验事实和核心方法保持不变。

### 2.2 代表论文的研究结构

以下总结是对代表论文的阅读归纳，而非期刊强制模板。

| 代表工作 | 科学瓶颈与主要思想 | 证据组织 | 应借鉴的研究方式 |
| --- | --- | --- | --- |
| Enabling local neural operators to perform equation-free system-level analysis，NMI 2026 [P1] | 将局部 NO 从时间预测推进到固定点、稳定性与分岔等系统分析 | 三类非线性 PDE 的不同分岔行为；局部学习、Krylov 和多尺度计算形成任务链 | 强调新增的科学分析能力，不只是预测更快；公开页面可核查摘要与图注，付费正文未全部核读 |
| Deep neural operator for free boundary problems，NMI 2026 [P2] | 以共轭系统和几何映射处理解域事先未知的学习对象 | 方法构造、近似定理、Stefan、热结构耦合与肿瘤生长等实例 | 统一框架建立在同一个数学困难上，不是把不同 PDE 强行放进相同代码 |
| Fast-forward prediction of lattice Boltzmann dynamics with physics-informed neural operators，Nat Commun 2026 [P3] | 直接学习分布函数的大时间跳跃，并保留矩与对称性结构 | 多种动力学、表示对照、物理量、分辨率与成本分析 | 保留对任务有意义的状态结构；架构本身不是全部贡献 |

P3 的公开审稿文件实际追问了：为何不直接预测宏观量、参考模拟是否验证、CPU/GPU 比较是否公平、训练成本和摊销是否完整。[P4] 因此本项目把“最直接的替代方案、独立真值验证、完整成本”列为研究设计内容，而不是投稿后补救。

书目信息核对：P1 的 DOI 是 `10.1038/s42256-026-01265-1`；`10.1038/s41467-026-75730-1` 对应 P3，二者不可混引。

### 2.3 本项目追求的证据链

~~~text
科学需求 → 可重复现象 → 前人解决到哪里 → 尚未解决的机制
                                               ↓
独立复现 ← 科学后果与综合收益 ← 区分性实验 ← 由机制推出的方法
~~~

一个有价值的选题应在“假设已经完美解决”时仍值得领域读者关注。重要性可以来自新能力、新规律、关键失败的解释或有实际后果的技术突破，不由榜单名次单独决定。

一般性优先建立在共同机制及其适用条件上，再通过不同物理、几何或尺度验证。增加相似 benchmark 的数量不自动增加一般性；一个边界清楚、具有广泛科学意义的问题，也不必靠覆盖所有 PDE 获得价值。

## 3. 目录与信息管理

### 3.1 复用现有目录

本规范放在 `Nature/RESEARCH_PROTOCOL.md`。已有 `Nature/interface_transfer/`、`research/transport_lifting_corrector_v1/` 和 CDMC 历史线保留各自身份，不搬动、不覆盖，不强行合并为一种方法。

今后研究项目优先复用对应目录。确需独立新线时，在 `Nature/<topic>/` 建一个项目根；以研究对象命名，不以每次模型版本命名。首次建立只需以下核心文件，其他目录有实际产物时才创建：

~~~text
Nature/
  README.md                    总入口和本规范链接
  RESEARCH_PROTOCOL.md         本研究规范
  RESEARCH_TEMPLATES.md        集中放置可复制的记录模板
  <topic>/                     已有或确有需要的新研究项目
    README.md                  状态、当前候选、关键结果、下一步
    QUESTION.md                研究立论、可证伪假设、价值及验收目标
    LITERATURE.md              文献事实、直接前作和重叠审计
    METHOD.md                  当前完整方法及其设计依据
    EVIDENCE.md                主张—证据总账、结果索引
    LOG.md                     追加式研究判断和失败记录
    src/                       方法、适配、训练、评测与诊断代码
    configs/                   数据、实验和准出协议
    runs/<run_id>/             不可覆盖的运行记录
    manuscript/                持续更新的论文、图表源数据与最终稿
~~~

已有项目不必机械重命名。例如已有 `CURRENT_METHOD.md` 和 `RESEARCH_NARRATIVE.md` 可继续使用，但 README 必须指出唯一的当前方法和叙事入口。不要再创建一批内容重复的 FINAL、LATEST、NEW、V2_FINAL 文档。

### 3.2 文档、计算和存储的职责

| 对象 | 放置与维护规则 |
| --- | --- |
| 当前判断 | README 简短呈现；下一步仅列最关键的待决问题 |
| 问题与指标 | QUESTION 保存当前定义；改变时在 LOG 记录动机和影响 |
| 文献 | LITERATURE 记录 DOI、版本、原文位置、事实、解释和证据范围 |
| 方法 | METHOD 写清完整输入到输出及物理/数学；代码细节留在 src |
| 每次运行 | runs 中保存配置、来源清单、日志、结果和必要图表，不覆盖旧运行 |
| 原始指标 | metrics.json 与 per_sample.csv；汇总表由脚本生成 |
| 决策 | LOG 追加事实、竞争解释、选择和返回节点；不另建零散日报 |
| 论文 | manuscript 持续更新；正式图表关联已锁定运行及源数据 |
| 大数据、权重、缓存 | 默认留服务器；本地只保留代码、必要小结果、文档和图 |

本地与远端项目保持相同的相对路径，远端根为 `/data1/caohuilin/Graph`。服务器默认只同步运行所需代码、配置及小清单，不同步大量本地写作文档，不使用 `--delete`。只使用允许的 conda 环境；本地使用已有 .venv，不安装 torch 等训练依赖。连接信息不写进论文、日志或可发布配置，遵守 AGENTS.md。

### 3.3 没有 Git 也能追溯

研究不以恢复 Git 为前提。每个有效运行保存源码清单和 SHA-256；对参与该次结果的代码保存小型源码快照或可恢复的补丁。数据、划分、权重、配置各自记录哈希。复用历史结果时引用原运行，不复制成“新结果”。

## 4. 研究闭环与阶段门

### 4.1 完整流程

~~~text
A 价值立论与文献核查
        ↓
B 现象审计与机制分析
        ↓
C 核心洞见与最简方法
        ↓
D 单次快速实验 → 误差/成本分析 → 针对主要障碍改进
        ↓                         ↖ 必要时返回 A、B、C
E 候选冻结与准出验证：多 seed、独立留出、正式计时
        ↓                         ↖ 不通过则返回实际出错环节
F 整体审计、论文整合与复现交付

写作、证据登记与研究日志贯穿 A—F，不等到 F 才开始。
~~~

阶段门决定投入规模，不是让研究卡在手续上。快速阶段可以在一条日志内完成判断；只有候选冻结和准出需要完整清单。

### 4.2 阶段产出和返回规则

| 阶段 | 必须形成的认识或产物 | 进入下一阶段的依据 | 未通过时 |
| --- | --- | --- | --- |
| A | 问题立论、直接前作、价值来源 | 问题有实际后果，文献存在具体缺口，能设计反证 | 重新调研、修正或更换问题；保留价值判断 |
| B | 可信参考、失败审计、主要机制及替代解释 | 现象真实，机制有可验证预测 | 返回数据/算子/评价审计或修正机制 |
| C | 一个中心洞见和完整简洁方法 | 与前作差异实质存在，流程可实现，关键收益可检验 | 改表示、学习任务或计算分工，而非堆模块 |
| D | 一次运行的配对结果、瓶颈分析和下一判断 | 同协议下收益有意义，机制没有被反证 | 回到最大障碍所在环节 |
| E | 冻结候选的多 seed 与独立验证 | 主张跨随机性和目标变化成立，成本与精度可信 | 恢复开发；记录被使用的留出集 |
| F | 可审阅论文和从源码到图表的复现包 | 科学价值、创新、证据、写作和开放材料整体合格 | 返回对应环节，不以材料齐全代替科学完成 |

“完成研究”指达到整体验收，不指跑完预先列出的所有命令。阶段进展必须来自新认识、有效方法或关键证据，不以运行数量计数。

## 5. 价值立论与文献核查

### 5.1 问题立论的内容

先在 QUESTION 用一页形成：科学/工程需求、可观测失败、失败后果、前人最佳能力、具体剩余缺口、共同机制、可证伪预测，以及成功后能够改变的认识或能力。

事先给出有意义的效果尺度，例如任务容许误差、功能判断偏差或可接受的完整成本；依据来自物理、应用需求或直接前作，而不是观察结果后选择刚好能通过的阈值。数字可随认识修订，修订原因进入 LOG。

问题既可起于科学需求，也可起于意外实验发现。无论起点如何，进入方法研究前都要解释：为什么这个失败重要，为什么现有最直接方案不足，为什么结果有望超出单个样例。

### 5.2 文献核查路径

按“问题来源 → 最直接竞争方法 → 数值/数学基础 → 相邻领域启发 → 最新竞争工作”调研。最近工作持续更新，经典基础也要核查，不能只搜新模型名称。

对每篇核心论文记录：

- 标题、作者、年份、正式发表/预印本状态、DOI 和读取版本；
- 研究对象、输入输出、训练目标、核心计算和在线成本；
- 数据生成、划分、参考精度、指标、对照和泛化设置；
- 作者明确报告的限制及对应原文位置；
- 我们从其结果作出的推断，与作者结论分开；
- 与拟议方法相同的部分、实质差异和可检验的新能力。

先读直接前作的正文、公式、关键图表、Methods 和有关补充材料；需要复现时核查官方代码。综述或 AI 总结用于找线索，不替代原文。付费或无法访问的内容标明读取范围，不补写没有核查过的细节。

### 5.3 创新性审核

采用三个比较层次：

1. **问题层：** 目标现象、物理后果或统一规律是否已经被提出并验证？
2. **方法层：** 将名称去掉后，我们的公式、信息流、学习任务或计算结构与前作差在哪里？
3. **证据层：** 新方法获得了哪一种原方法没有证明或处理不好的能力？

借鉴传统方法或已有网络是合理起点；贡献必须落在新的机制理解、表示、学习/计算耦合、理论规律或有重要意义的系统能力上。共享 encoder、增加输入、拼接两个模块不单独算作论文级创新。也不要求每一层神经网络都原创。

冻结候选前和最终稿准出前各重新核查最接近竞争工作。发现高度重叠时，优先找到真实剩余问题并重新设计，不通过重新命名或删去引用制造空白。

## 6. 机制分析与理论要求

### 6.1 先识别主要障碍

| 障碍 | 首选诊断 | 诊断结果如何指导方法 |
| --- | --- | --- |
| 输入缺少决定性信息 | 相同可见输入、不同目标的对照；细信息恢复对照 | 改输入协议或足够统计表示，单纯加容量无效 |
| 输出表示或恢复不合适 | 固定上游，以已知正确中间量检查恢复能力 | 改输出坐标、相容空间或重建；oracle 仅作离线诊断 |
| 训练目标与物理目标错位 | 同一预测下比较场、导数、响应及功能误差 | 改目标或物理读出，解释两种误差之间的关系 |
| 标签、在线算子与评价不一致 | 真值代回、独立求解、边界和分辨率核对 | 先修正协议，避免校正到错误离散根 |
| 主要误差未被方法处理 | 误差按物理区域、尺度或算子模式分解 | 调整核心传播与学习分工，而非盲目加深 |
| 泛化失效 | 分开变化材料、几何、尺度、激励与组合 | 找到失效变量，再判断是否违反方法假设 |
| 时间居高不下 | 完整执行的阶段分解及复杂度分析 | 优先处理支配项；区分工程常数和算法结构 |

### 6.2 理论服务于可检验判断

理论分析至少对一个关键判断提供解释或预测：为何现有目标不能控制所需响应、何种信息不可缺、为何某种表示减少学习困难、误差如何传递、计算规模为何改变收益，或方法在哪些条件下成立。

推导按“变量定义 → 物理假设 → 离散/算子关系 → 中间步骤 → 命题 → 可验证后果”展开。近似、边界条件、正则性、SPD 等假设须在使用前给出。区分数学恒等式、带假设命题和实验假说；不得以通用逼近能力替代实际泛化或有限成本下的优势证明。

小型解析/合成问题用来隔离机制，真实或公开样本用来检验其实际意义。离线使用真值、中间 oracle 或精确辅助求解时，结果明确标为诊断，不进入部署方法或预测精度主表。

## 7. 方法设计与整体优化

### 7.1 从洞见到完整预测器

先写中心洞见，再确定信息、表示、物理接口、学习任务、网络和恢复。METHOD 必须从输入一直写到最终可用输出，覆盖：

1. 统一问题和主要假设；
2. 离散或数据适配，以及保留了什么信息；
3. 所有在线数值和神经步骤；
4. 神经网络内部结构、输入通道、消息/注意力/谱计算、输出坐标；
5. 输出如何满足必要相容性、恢复为状态及物理观测；
6. 训练数据、监督、损失和选模协议；
7. 适配分支的触发条件与理由，不以 PDE 名称随意加模块；
8. 复杂度、完整成本、可复用计划和实际边界。

本规范不预设局部—整体、多重网格、PCG、后校正或某个 backbone。是否采用由问题机制决定；已有方法按证据复用，不因历史惯性强行保留。

### 7.2 简洁性准则

每个新增模块需写清：解决哪个主要障碍、利用什么已知结构、增加多少成本、用什么实验可证明其必要性。多个模块可以服务于同一核心原则，但不能为每个失败点添加互不关联的补丁。

先尝试最直接、最简的替代方案；如果它已经解决问题，应据此提高目标或重新评估研究价值。若组合才是贡献，检验各部分为何必须协同，而非只证明“组件越多越好”。

### 7.3 优化次序

先校验参考与目标，再定位主误差或支配成本，然后修改决定该障碍的结构。训练配置和实现优化放在机制正确之后。机制收益明显但成本稍差，可以测出工作区间；不能把低 GPU 利用率造成的偶然速度当算法贡献。

一次方法级修订可以同时改变相互依赖的多个接口，但日志要解释其共同原因。快速阶段不要求先做完整全因子消融；最终核心消融再区分联合设计中真正起作用的部分。

## 8. 实验设计与快速迭代

### 8.1 开发与准出分开

| 项目 | 快速开发阶段 A—D | 最终准出阶段 E—F |
| --- | --- | --- |
| 训练次数 | 每个配置一次训练，固定开发 seed | 候选冻结后，按待证明的稳定性安排多 seed |
| 评测 | 一次评测覆盖预定样本和必要切片，复用逐样本结果 | 在锁定协议和独立留出上确认结果及不确定性 |
| 消融 | 只做能区分当前竞争解释的关键对照 | 系统验证核心洞见、机制与必要组件 |
| 计时 | 一次简短测量，足以定位主要成本 | 正式 warmup、重复测量、分布和环境记录 |
| 数据与规模 | 最小但有代表性的开发集，包含目标困难 | 检查中心结论所需的物理、几何、尺度和边界情形 |
| 决策 | 看机制、效应量和逐样本差异，快速选择下一步 | 看科学意义、稳健性、完整代价和证据覆盖 |

**快速阶段不以“更稳妥”为由重复训练同一配置，不提前做多 seed，不为每个候选重跑完整 benchmark。** 一次训练中的正常验证、一次评测中的多样本统计，不算重复实验。不同 PDE、几何或尺度是在验证适用性，也不等于重复 seed。

异常复测只用于具体问题，例如任务意外中断、结果文件损坏、明显计时干扰或疑似实现错误。先保留原记录，写清异常与复测理由；有效但不理想的结果不能改名为异常后反复重抽。断点续训沿用原运行，协议或方法实质改变才建立新运行。

最终多 seed 的数量及分配依据效应大小、计算成本和主要主张确定，在看准出结果前锁定；Nature 没有适用于所有此类工作的统一 seed 数量门槛。冻结的基底与新训练校正器分别记录 seed，明确统计覆盖的是哪一部分随机性。

### 8.2 每轮实验的最小单元

一轮研究以一个待决假设为单位，不以一个模型名称为单位。运行前在 LOG 或实验配置中写清：

1. 现象与竞争解释；
2. 本轮改变，以及预期通过什么机制生效；
3. 共用数据、基底、训练量和评价协议；
4. 主指标、必要辅助指标及有意义的变化尺度；
5. 什么结果支持、反驳或仍不足以区分这些解释；
6. 一次训练和一次评测的命令、输出路径、开发 seed；
7. 各种结果分别导向的下一步。

优先复用已有预测、权重和真值做离线诊断，再做小型机制实验；机制通过后才增加训练量或问题规模。若验证的是更好的训练方法，同等训练预算和相同最终质量下的训练成本都应成为比较依据。

### 8.3 失败后的返回规则

| 观察 | 优先行动 |
| --- | --- |
| 参考解、物理算子或指标不可信 | 停止架构比较，先修正实验有效性 |
| 理想中间量也不能改善最终目标 | 回到表示、数学接口或恢复步骤 |
| 理想中间量有效，模型学不到 | 分析可辨识性、训练分布、表示与容量，不先堆训练时长 |
| 平均提高，关键困难样本持续失效 | 识别共享失效机制，检验是否关系到中心主张 |
| 精度改善但成本超出有效区间 | 按端到端剖析重分配计算，不只优化单个 kernel |
| 简单替代方法取得同等效果 | 重新审视中心洞见及新增结构的必要性 |
| 直接竞争方法已经充分解决问题 | 回到研究缺口，不继续制造弱对照 |

连续两轮对同一个机制的改动没有产生新认识时，默认触发一次整体复盘：是否错认主要误差、目标是否可观测、数值根是否一致、模型承担的任务是否过重。这是防止原地打转的内部提醒，不是“只允许尝试两次”的硬配额。

有价值的负结果进入证据总账。方法失败与实验无效分开；前者提供科学认识，后者修复后才能参与比较。

## 9. 数据、基线与评价协议

### 9.1 参考解和数据审计

数据卡记录原始来源、许可、生成方程、参数、单位、网格/单元、边界与初值、时间采样、参考求解器、容差、精度和归一化。条件缺失时写清缺项如何影响所做比较，不自行补成作者未提供的生成协议。

自生成数据须用解析解、网格/时间加密或独立成熟求解器验证参考精度；不要求每个样本重做高成本参考。用于关键物理结论的样本必须有足够的参考可信度。插值、下采样、边界消元和场恢复后的标签再次检查，避免将数据处理误差当作模型误差。

数据标签对应的解、当前离散算子的根和目标物理观测分别定义。若存在离散偏差，报告其量级及来源；不能只凭某个自定义残差下降推断解更接近参考。

训练、开发与最终留出按独立物理样本划分。同一轨迹的时间窗、同一几何的网格版本和同一实例的不同激励可能相关，划分单位应匹配所声明的泛化。训练统计不使用最终留出信息；每次因最终结果而改方法，都记录该留出已参与开发，并按实际独立性安排新的最终确认。

### 9.2 选择有判别力的基线

优先回答“领域研究者不用我们的方法，最可能用什么解决这个问题”。最小集合通常覆盖直接神经预测、成熟数值求解、最接近的混合方法和最直接的简化替代；具体是否需要某类，由研究主张决定，不为凑表格引入无关方法。

| 对照类型 | 实现与比较要求 |
| --- | --- |
| 神经基底 | 核查官方预处理、边界处理、结构、损失和训练配置；当前效果偏离参考时先定位原因 |
| 数值求解 | 使用适配方程结构的成熟实现、合理预条件和停止规则；验证实际场/功能精度及完整时间 |
| 直接前作 | 优先官方代码；复现缺失部分逐项说明，不将大幅简化版本标成原方法 |
| 简化对照 | 相同可用信息和预算下，检验最简单处理是否已足够 |
| 核心消融 | 各行对应一个关键科学解释；控制其余条件，必要时加入替代机制而不只删除组件 |

兼容性矩阵先于批量运行：方法是否支持当前网格、输入信息、边界、方程结构及时间协议。不能把规则网格方法静默改造后仍标原名，也不能让不支持的分支返回 identity 占位结果。

所有部署比较列出可见信息与费用：方程、系数、网格、历史帧、基底特征、求解器访问等。方法使用额外物理信息时，提供共享该信息的直接替代或单独比较；训练标签、参考解或由其选出的区域只出现在明确标识的诊断中。

论文报告数字与本地复现分栏，写明数据版本、分辨率、预测跨度和硬件。跨硬件论文时间用于背景，不直接计算方法加速比。对复现差距核查协议及实现，不把短训弱基底作为优势来源，也不无上限补训基底而偏离主要研究。

### 9.3 指标服务于科学问题

预先指定主要物理/科学指标和对应理由，保留领域通用指标以便比较。[S4] 根据任务需要选用以下层次，不机械地每项都做：

- **目标后果：** 与中心问题直接对应的响应、交换、事件、稳定性或决策误差；
- **状态与结构：** 全场误差、局部/导数误差、边界和相容性，以及关键区域或模式；
- **分布：** 逐样本配对差异、分位数、失败率和预定困难切片，而不仅是均值；
- **泛化：** 共享困难机制在参数、几何、尺度、激励或物理变化下的表现；
- **成本：** 完整时间、前置成本、显存/内存、训练数据量及离线投入。

公式说明归一化、权重、量纲、方向和近零分母处理。不规则网格采用与物理积分一致的权重；局部区域由预定物理规则或部署可用信息确定，不能按哪种方法表现最好事后挑区域。相对降误差同时给原始数值，防止微小分母制造大比例。

快速阶段用固定开发 seed 和逐样本结果分析机制；最终对独立样本与训练随机性分别量化不确定性。存在轨迹或几何内相关性时按对应独立单位统计，不把大量相关网格点当成独立实验。

## 10. 时间、内存与复杂度

### 10.1 端到端成本边界

在 METHOD 与结果表统一使用以下分解；实际不存在的阶段记为不适用，不强行增加计算：

| 阶段 | 应包含内容 | 可复用条件 |
| --- | --- | --- |
| 离线 | 数据生成、基底训练、附加模块训练、超参探索 | 由训练覆盖范围决定 |
| 一次性运行准备 | 权重载入、框架/内核初始化、JIT 或图捕获 | 同进程、同形状/执行条件 |
| 网格计划 | 连通性、几何量、层级、插值与静态索引 | 相同网格和边界结构 |
| 样本系统 | 系数、边界/源项、矩阵或矩阵自由算子、粗层更新/因子 | 相同算子或可证明复用的部分 |
| 直接预测 | 输入变换、NO 执行、必要输出解码 | 每次预测执行 |
| 物理/学习更新 | 缺陷、网络 setup、校正、迭代和必要线性求解 | 按真实依赖分别计入 |
| 输出恢复 | 场重建、跨域读出、必要传输与最终物理量 | 每次输出执行 |

至少区分三种在线场景：新网格新系统的冷启动、固定网格但系数变化、同一算子多次查询。训练完成和权重已驻留属于常见服务假设，但权重加载及编译的代价另列。哪部分可摊销，由几何、参数和边界的实际变化决定，不能把变化部分标为缓存。

### 10.2 测量规则

单样本延迟与批量吞吐分开。GPU 计时等待相关工作完成，CPU—GPU 搬运、Python 调度和系统构建不能因只计 GPU kernel 而从端到端时间中消失。使用壁钟和设备事件时分别注明它们回答的问题。

warmup 是预热初始化/执行路径，不是模型训练；repeats 是测量同一冻结程序的运行波动，不是重新训练 seed。快速阶段只做必要的小规模预热和一次简短计时，不为每个候选执行大量重复。低于计时分辨率时可在一个测量窗口内连续执行少量调用，记录次数与摊销方式；正式的反复计时只在候选准出时进行。

计时记录硬件、软件、dtype、batch、网格/自由度、线程数、GPU 是否共享、缓存状态、warmup 与测量调用数、同步方式、统计量和包括/排除项。端到端总时间单独实测，阶段剖析另做；嵌套事件、重叠并行和额外同步会使阶段和不等于总时间，不能直接相加伪造总耗时。

比较数值与学习方法时展示同精度所需时间或误差—时间曲线，不只比较相同步数。曲线每个点对应真实配置和记录；同一执行可记录中间精度检查点，但正式延迟测量避免把诊断开销算进某一个方法。不同硬件部署可另展示实际使用成本，与同硬件算法比较分开。

### 10.3 规模与摊销

复杂度分析给出自由度、边/非零元、层级、通道/秩和迭代次数的定义；写清构建、存储和每次执行的复杂度。不能预设传统方法总是三次复杂度，或将固定小网格的 GPU 常数优势外推为大规模算法优势。

需要频繁查询时，分别估算离线投入、每次新系统构建和单次执行，在真实复用窗口计算摊销；若不存在正的盈亏平衡点，就解释收益来自新增能力、可靠性还是其他科学价值。已有训练资产可复用时列出新增成本，同时保留完整研究投入记录。

## 11. 研究记录与证据管理

### 11.1 每次运行保留什么

每个 run_id 唯一且不可覆盖，保存解析后的配置、命令、输入/划分/权重/源码标识、环境、固定 seed、开始结束时间、退出信息、原始日志、指标与逐样本结果。大权重与预测留服务器，以路径和校验值索引；只对参与结论的材料做必要归档，不复制整个数据集。

运行状态按实际生命周期记录：`planned → running → completed / failed / aborted`。科学解释单列：`supports / refutes / inconclusive / invalid`。训练跑完但假说失败，状态仍是 completed、解释是 refutes；代码错误产生的结果是 invalid，不伪装成方法性能。

开发记录可简短，但必须能重建“用哪版代码、哪份数据、什么条件得到哪一项结果”。缺失出处的历史数字先标记待核查，不直接放入正式主表。结果表由结构化原始指标生成，不手工维护一套相互冲突的表。

### 11.2 主张—证据总账

EVIDENCE 中每个主要主张有独立编号，链接支持实验、理论、对应基线、反例、科学效应量和待补证据。证据状态区分开发支持、独立确认、被反证和待验证，不把设计预期写成已完成。

LOG 按研究决策节点追加，而非按工具调用追加：结论、改变结论的证据、下一决策即可。命令、异常堆栈、逐样本数字留在运行记录；只有影响实验有效性或科学判断的异常进入LOG。旧方案可被替代，但保留当时结果和理由。方法、代码、图表同步引用当前候选，历史最优行不能混装成一个从未完整运行过的方法。

### 11.3 报告与运行可读性

每个实际研究项目提供简洁统一的运行入口，覆盖数据、训练、评测、诊断、结果导出；按真实需要扩展，不先开发通用平台。公共评测和计时复用，方法与数据适配各有清晰模块，不复制一份完整管线作为新方案。

README 的状态表至少回答：什么已完成、什么在运行、用了什么候选、证据支持什么、下一步是什么。正在运行时给真实进度与已观测速度；没有足够信息时不猜完成时间。暂停/交接时写明运行位置、作业标识、检查点及恢复方式。

## 12. 持续写作与图表规范

### 12.1 由研究推进稿件

| 研究进展 | 同步形成的稿件材料 |
| --- | --- |
| 立论成立 | 背景、问题后果、前人路径和准确的剩余缺口 |
| 机制得到支持 | 关键观察图、推导及其可检验预测 |
| 方法可执行 | 完整方法、结构图、输入到输出算法和训练目标 |
| 得到有效结果 | 对应 Results 小节、源数据、效果量及解释 |
| 候选准出 | 摘要、整体论证、Discussion、复现材料和投稿配件 |

日常稿件使用“已观察”“机制假说”“拟验证”区分证据状态；最终稿由已确认的主张构成。新结果改变认识时同步改稿，不保留与证据相反的早期叙事。

### 12.2 论文组织

按“重要需求 → 关键观察 → 未解决机制 → 研究原则 → 验证与科学后果”组织论证。相关工作沿问题的研究路径展开，说明与本研究的关系，不按作者名单逐篇罗列。[W1]

| 部分 | 内容重心 |
| --- | --- |
| 标题与摘要 | 科学问题、中心进展、最关键证据与意义；数值均可追溯 |
| Introduction | 为什么重要、现有路线如何发展、具体缺口、本文改变什么 |
| Results | 用逻辑递进的主张组织小节：现象、机制、方法能力、意义与适用性 |
| Discussion | 提炼认识与实际价值，解释观察到的适用条件和未来问题 |
| Methods | 完整数学、物理假设、模型内部结构、训练、数据、基线与统计 |
| Supplementary information | 支撑性推导、额外验证、完整参数、次要结果与复现细节 |
| 可用性声明与源数据 | 数据、代码、模型、图表数据、许可及 AI 辅助研究说明 |

这是一种论证结构，不硬编码每个期刊的章节、篇幅和图数；投稿前按目标期刊与文章类型的最新官方规范核查。[S5–S7]

“正面写作”要求以机制和实证陈述贡献，例如“该表示恢复了某类方法遗漏的响应，效果在这些独立条件下保持”。它不等于夸大首创、隐藏失败或删除边界；将边界写成有解释力的规律及下一步科学问题，而不是全文反复强调“不能说什么”。

### 12.3 图表与来源

每张图解决一个明确的判断：问题是否真实、原因是否成立、方法如何运行、优势是否实质、规律能否迁移。需要的主图由证据链决定，不先规定固定数量。

科学结果图用真实样本和可复现绘图程序生成；概念示意与数据图明确区分，生成式示意不得冒充模拟、测量或方法输出。样本展示同时考虑预先规则选出的代表样本和困难/尾部样本，避免只展示最有利案例。

图注自包含，给出条件、单位、独立样本单位、方法、指标、统计含义及颜色；方法对照尽量统一坐标、色标与裁剪。表格标明指标方向、原始误差和改善比例、时间范围及配置。[W1] 主张、公式、模块名称和图中标注前后一致。

每个面板关联 run_id、样本标识、源数据和绘图命令。图表源数据从研究期保留；官方投稿对相关稿件可能要求对应的源数据文件，核心代码须可审阅。[S5–S6]

## 13. 候选冻结与最终准出

### 13.1 冻结内容

当开发证据同时支持问题价值、核心机制、实质创新与实际收益时，冻结候选方法、代码/权重、数据划分、指标、基线配置、选模规则和验收目标，再做最终多 seed 与独立确认。不能按最终结果筛选最有利 seed，不能为得到期望结果持续添加隐藏尝试。

最终确认集中于论文中心主张和最强竞争解释，不把所有开发候选全部多 seed 重跑。对于纯推理的确定性方法，重点验证跨独立实例/条件和计时波动；不为凑 seed 人为制造无意义随机性。对训练方法需覆盖所声称的训练随机性。

### 13.2 整体准出矩阵

| 维度 | 准出时需达到的状态 | 不满足时返回 |
| --- | --- | --- |
| 问题价值 | 失败有明确科学后果，解决它带来实质认识或能力 | A：立论与前人工作 |
| 创新性 | 最接近前作已核查，差异不依赖命名，新增能力有证据 | A/C：缺口与方法 |
| 机制 | 中心解释经区分性实验检验，关键替代解释已处理 | B/D：诊断 |
| 方法完整 | 部署输入到最终输出连贯、简洁，训练与测试一致 | C/D：设计与实现 |
| 实际效果 | 对最强相关替代有科学意义的收益或明确的新能力 | C/D：主要瓶颈 |
| 一般性 | 共同机制与代表性变化一致，适用条件有理论/实证依据 | B/D：机制与验证 |
| 可信度 | 参考、基线、留出、统计、成本和失败记录均可核查 | D/E：协议与确认 |
| 复现与写作 | 主张逐项有源数据，代码/文档一致，稿件能独立读懂 | F：整体整合 |

不能以“小幅平均涨点”“目录齐全”或“命令全部跑完”代替整体通过；也不强制所有指标、所有实例都胜出。准出判断依据事先确定的中心目标、科学效应及权衡，结果不符合目标时继续解决主要问题。

### 13.3 准出审核与交付

先做反方自审：最强替代是否更简单有效、真值是否足够精确、收益是否来自额外信息或预算、是否有被平均数掩盖的关键失败、机制与结果是否一致。再从保存的环境、配置和源码复现至少关键证据链，核对表格、图注、摘要中的每一项数字。

交付当前方法、文献核查、证据总账、决策日志、最终指标/曲线、源数据、运行命令、环境与版本标识、稿件及复现说明。提供独立研究者可审核的材料，人类研究者复核核心科学判断、署名责任与最终投稿。实质 AI 辅助研究按政策透明披露，不能将其伪称为未经辅助的人类推导。[S7]

本规范用研究质量和证据完整度判断“具备投稿准备”，不将内部通过视为期刊录用保证。

## 14. 自主研究的执行与恢复

### 14.1 每次启动或继续

1. 首次接入读本规范；续接优先读项目的一页工作状态和 README 当前入口，确认用户最新目标、限制与暂停状态。当前方法、证据总账和历史 LOG 按本轮问题定位读取，不在每次恢复时全文重读。
2. 检查已有结果和实际运行状态，识别是否已有相同配置的有效运行；可续接的任务不重复启动。
3. 用一句话确定当前最大未知、最关键证据缺口和应返回的阶段。
4. 选择信息价值最高、代价合理的一轮动作；优先现有数据分析，其次单次小实验，再扩大验证。
5. 检查结果有效性，分析主误差/成本和替代解释；更新方法、证据、日志与对应稿件材料。
6. 形成继续、改方法、回机制、回调研、冻结候选或提交整体验收的阶段建议。
7. 交接时留下真实状态、关键结果、仍未解决的问题、下一条动作及恢复命令，不以冗长过程描述代替结论。

没有跨轮持久执行或任务调度时，文档只保证下次能够可靠恢复，不声称退出会话后仍在自动研究。用户要求暂停时停止启动新任务，说明已有任务状态；不能把“持续推进”当成无边界授权。

### 14.2 决策边界

在既有范围内可自主调研、分析、修改代码、做一次开发实验、整理材料与提出方法判断，不要求每走一阶段都等用户确认。决定性改动写清机制依据与记录。

需要新增权限、明显扩展科学目标、超出资源约定、修改无关项目、不可恢复删除或正式对外发布/投稿时，先请求研究者决定。删除原数据、覆盖历史主线和随意更改服务器环境不是研究迭代的默认动作。

研究过程保留工具/模型辅助记录与可验证产物；自动生成的判断属于供研究者复核的建议，而非替代人类科学责任。[S7]

### 14.3 规范的维护

规范随真实研究教训修订，记录版本和改变理由，不因单次候选不达标而降低价值标准。项目可以进一步简化不必要手续，但保留假设、证据来源、实验有效性和决策理由四条最小线索。

可复制模板统一位于 [RESEARCH_TEMPLATES.md](RESEARCH_TEMPLATES.md)，总入口位于 [README.md](README.md)。本次规范建设不触发任何新训练或数据生成。

### 14.4 上下文与研究注意力

- 每个项目最多维护一页 `WORKING_STATE.md`，仅保存目标、冻结候选、决定性证据索引、当前唯一瓶颈、下一动作与停止条件；它是恢复书签，不另写一套方法或结果。
- 阅读顺序为工作状态 → 本轮相关函数或证据段 → 必要原文。使用定位搜索与限长输出，避免整份历史日志、JSON、源码反复进入上下文。
- 每轮只解决一个能够改变研究判断的主要未知；完成后回到第13.2节检查整体目标，不能把参考修复、环境调试或末位精度优化变成长期研究方向。
- 若连续两轮没有新增机制认识、有效能力或关键反证，停止同一路径的细调，回到问题、表示或方法层作一次整体判断。
- 归档历史不删除证据。恢复时默认不读历史细节；只有需要追溯具体数字或竞争解释才按索引打开。
